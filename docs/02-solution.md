# 02 方案设计与技术取舍

## 调用流程

`CLI → Agent → 模型动作 → 工具 → 观察 → 下一轮模型动作`，直到完成或达到步数上限。预设部分只有动作协议、工具白名单、格式与引用校验、执行上限，不在 live 模式硬编码“某关键词对应某动作”。

每轮向模型发送系统约束、问题与可选历史、此前动作及真实工具观察。模型可以多次 search、选择 read、调整查询、停止或追问。工具失败也以观察反馈给模型，而不是由运行时静默自动重试。运行时拒绝不合法的动作或引用，并把拒绝原因交回模型继续处理。

动作对象为 `{action,args,reason}`。search 参数为 query，read 参数为 doc_id，finish 参数为 status、answer、citations、gaps。reason 是短操作依据，不是内部推理记录。

## 两条应验证的真实决策路径

1. 明确资料：模型检索 → 看见候选 D01 → 读取 → 看见 30 天原文 → 回答并引用。
2. 冲突资料：模型检索 → 看见 D01 和 D02 → 分别读取 → 看见 30/15 天且缺少适用范围 → 引用双方、请求确认。

另有“无命中→改写检索”和“读取失败→重试/停止”路径。当前同形的离线实际记录在 examples/mock/，这些只是流程样例，真实模型路径还未执行。

## 模块职责

- `models.py`：LiveModel 负责 Chat Completions JSON 适配和安全错误归类；OfflineMock 负责可复现的离线规则模拟。
- `tools.py`：本地字符二元组/英文 token 匹配检索，返回最多 8 条候选及版本；read 获取完整原文，成功后才登记为可引用证据。
- `agent.py`：注入模型与工具、保留观察、驱动有界循环、校验完成动作、汇总输出。
- `cli.py`：运行参数、合成故障注入、文件读写、退出状态。

## 证据与边界

引用必须指向本轮成功读取的文档，quote 必须为非空逐字子串。历史助手答复、检索摘要和读取失败结果不能充当引用。每轮运行清空证据池，避免跨任务误用。

这一校验只能证明“引用确实存在于读取的原文”，**不能自动证明答案的语义被引用蕴含**，也不能证明模型没有遗漏冲突。语义支持、候选相关性和适用范围判断由模型负责，需真实运行和人工核验。

文档版本日期只作为证据，不自动决定优先级。冲突识别在 live 模式由模型基于原文完成。Mock 的多正文差异检测比较保守，不具备通用语义冲突判断能力。

## 工程取舍

采用 Python 标准库和原生循环，避免为小规模合成资料增加向量库、框架或多 Agent。便于评审直接运行和定位动作变化。检索无需下载依赖，但同义词、长文和排序能力有限；live 模型可以通过改写查询弥补一部分，不能保证召回完整。

模型接入采用 JSON 动作协议而非原生 function calling，以便复用同一个运行时校验器。供应商须支持 Chat Completions 和 JSON object 模式；当前只做本地伪服务协议测试，尚未实测外部供应商。

每次决定计入一步，工具调用最多等于 max_steps，默认 10。无隐式无限重试。单次网络调用有超时；无严格的总墙钟时间限制和 token/费用预算。无自动 Mock 降级。
