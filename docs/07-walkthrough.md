# 代码理解与演示准备

## 这个项目解决什么

员工询问制度时，系统要先找资料，再核对原文。资料冲突时帮助用户确认适用制度；没有资料时如实说明不足。可靠性优先于“每问必答”。

## 关键代码阅读顺序

1. `scripts/run.py` → `src/enterprise_qa/cli.py`：理解输入和运行模式。
2. `models.py` 的 SYSTEM 和 LiveModel：模型每次返回一个动作对象；HTTP 请求中包含此前实际观察。
3. `agent.py` 的 run：观察如何反馈到下一轮，为什么达到上限必须 incomplete。
4. `tools.py`：search 只有候选摘要，read 成功后原文才成为本轮可引用证据。
5. `agent.py` 的 validate_finish：检查引用来源和逐字原文；不声称完成语义蕴含验证。
6. `scripts/evaluate.py`：11 个输入、预期和可观察检查；真实运行不覆盖历史记录。
7. `tests/`：失败注入、修改文档、HTTP 伪服务、证据校验测试。

## 为什么是模型驱动的 Agent

live 路径中，运行时不根据问题内容硬编码下一步。模型看到检索、读取和失败结果后，自主选择下一次 search/read/finish；程序只限制动作范围、格式、引用及步数。预设的执行骨架符合规则，具体动作取决于本轮模型输出。

Mock 是另一套确定性规则，明确只用于离线测试，不证明模型能力。本地 HTTP 伪服务测试同样不是外部模型验证。

## 为什么没有向量数据库和框架

资料规模小、建议时间有限，标准库和原生循环足以完成核心链路，评审也能直接看懂动作变化。字符检索召回能力有限，这个代价已披露。规模增大时再引入更强检索，不能用框架名称代替效果证明。

## 演示建议

先展示真实正常场景，再展示真实冲突场景中的工具观察及下一步动作。然后展示读取失败时不会伪造成功，以及原文改成 45 天后的变化。每次引用实际运行文件，避免只展示截图。

## 可能被追问的问题

- 为什么不能直接采用更新版本？因为日期不等于优先级，适用范围和覆盖关系未提供。
- 为什么不只信搜索预览？摘要可能截断，最终引用必须来自本轮实际读取。
- 怎么避免循环？max_steps 计入每轮决定，超限明确返回 incomplete。
- 怎么验证模型因观察改变动作？看正常/冲突/失败/资料变更的真实 Trace，并对照输入与工具返回。
- 引用存在是否代表答案可靠？还不够，需要语义核验和冲突召回评估。
- 你个人做了什么？只能据自己的真实配置、运行、理解和修改记录回答，不照读 AI 的经历。
